# Business Requirements (RU)

Краткое ТЗ, зафиксированное при старте проекта.

## Проблема

Нужно валидировать и контролировать использование уникальных промокодов клиентов, снижая человеческий фактор и фрод сотрудников.

## Ограничения окружения

1. ERP (Granit): PostgreSQL/Firebird доступ только на чтение, схему ERP не меняем.
2. POS (шоп-челлер): оффлайн-касса, не редактируется; кассир бьет скидку вручную.
3. Стек: FastAPI, внешний PostgreSQL чекера, Docker; прод на Windows Server.

## Основной процесс

1. Маркетологи выгружают ID клиентов из ERP.
2. Скрипт генерирует уникальный 8-значный цифровой промокод и пишет в checker DB со статусом ACTIVE.
3. Telegram-бот отправляет клиенту штрихкод Code 128 (картинка генерируется на лету, в БД не хранится).
4. Клиент показывает штрихкод на точке.
5. Кассир сканирует аппаратным сканером (keyboard wedge) в веб-интерфейс чекера.
6. UI показывает: АКТИВЕН / ИСПОЛЬЗОВАН / НЕ НАЙДЕН.
7. Если АКТИВЕН: кассир вручную дает скидку в кассе, затем жмет «Применить скидку» → USED.
8. Hourly reconcile:
   - ищет ACTIVE
   - сверяет ERP продажи кофе со скидкой по customer_erp_id
   - если продажа была, а код ACTIVE → AUTO_CLOSE + erp_sale_matched
   - если MANUAL_CLOSE был, а продажи нет в окне → fraud warning

## Must-have cashier UX

- Absolute autofocus
- Только цифры, длина 8
- Enter от сканера = submit
- Debounce 1.5s
- Крупные цветные статусы
- Audio feedback

## Admin

- Отдельный вход
- Роли admin/viewer
- Обзор всех таблиц, логов, отчетов, алертов
- Полные ручные правки для admin с аудитом
